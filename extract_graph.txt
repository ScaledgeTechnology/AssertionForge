-Goal-
Given a hardware design specification document and a list of entity types, identify all entities of those types from the text and all hardware-relevant relationships among the identified entities.

The extracted entities and relationships should reflect the structure, components, protocols, configuration, constraints, and operational behavior described in the specification. This includes document structure, hardware modules, submodules, signals, ports, registers, clocks, FIFOs, standards, configuration rules, and references, without assuming any protocol-specific semantics unless explicitly stated in the text.

The goal is to extract entities and relationships with **engineering-level precision**, suitable for building a structured knowledge graph.

-Steps-
1. Identify all entities. For each identified entity, extract the following information:
- entity_name: Name of the entity, capitalized and normalized to match hardware terminology
- entity_type: One of the following types: [{entity_types}]
- entity_description: Comprehensive description of the entity’s role, attributes, configuration parameters, interfaces, and behavior as described in the specification
Format each entity as ("entity"{tuple_delimiter}<entity_name>{tuple_delimiter}<entity_type>{tuple_delimiter}<entity_description>)

2. From the entities identified in step 1, identify all pairs of (source_entity, target_entity) that are clearly related based on the specification.
For each related pair, extract the following information:
- source_entity: Name of the source entity, as identified in step 1
- target_entity: Name of the target entity, as identified in step 1
- relationship_description: Explanation of how and why the two entities are related based on hardware structure, behavior, or documentation context
- relationship_strength: A numeric score indicating confidence or clarity of the relationship (1 = weak, 10 = strong)
Format each relationship as ("relationship"{tuple_delimiter}<source_entity>{tuple_delimiter}<target_entity>{tuple_delimiter}<relationship_description>{tuple_delimiter}<relationship_strength>)

3. Return output in English as a single list of all entities and relationships identified in steps 1 and 2. Use **{record_delimiter}** as the list delimiter.

4. When finished, output {completion_delimiter}

-Additional Instructions for Hardware Design Specifications-
Ensure that all extracted entities and relationships align with hardware design documentation context, including:
- hierarchical document structure (sections, subsections, tables, figures)
- hardware blocks and sub-blocks
- protocols and standards explicitly mentioned
- configuration parameters, constraints, and operational limits
- signal roles, ports, and data flow relationships
- verification or dependency references (e.g., FPGA, tooling)

Do not infer protocol-specific behavior unless it is explicitly described in the text.
